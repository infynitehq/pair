# Pair interface states

`app/page.tsx` is a Server Component that renders the client `PairApp`. The UI consumes `PairSessionHook`; URL invitation detection and autojoin belong to the hook.

| State                         | Interface and available actions                                                                                                                                                                                                                                                                                                                                                         |
| ----------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Initializing (`ready: false`) | Initializing status; creation, joining, and browser-name editing are disabled. Initialization errors expose the error recovery screen.                                                                                                                                                                                                                                                  |
| `idle`                        | Editable browser display name, labeled connection-mode selector, create invitation action, and validated pasted-link join form. Automatic (default) permits direct connections with TURN fallback; Direct only never uses TURN; Relay only requires relay credentials. Selection calls `setConnectionMode`; persistence belongs to the hook/core. The selector is disabled until ready. |
| `creating`                    | Progress message and cancellation.                                                                                                                                                                                                                                                                                                                                                      |
| `waiting`                     | Real QR code, selectable invitation URL, clipboard copy with manual-copy fallback, invitation-expiry countdown, and cancellation.                                                                                                                                                                                                                                                       |
| `connecting`                  | Connection progress, invitation-expiry countdown when available, and cancellation.                                                                                                                                                                                                                                                                                                      |
| `verifying`                   | Peer name, full expandable browser identities, connection-check code, independent local and remote approval status, explicit approval, and cancellation. The code is described as a connection check rather than proof of real-world identity.                                                                                                                                          |
| `connected`                   | Peer name, actual direct/relay/checking route, encrypted-connection label, expandable identities and connection details, live conversation, sent/delivered status, 4,000-character text composer, reconnect, and disconnect. Ctrl/Cmd+Enter sends; Enter inserts a newline.                                                                                                             |
| `recovering`                  | The same Chat instance retains messages and draft. A polite status announces recovery and attempt number. Composer, send button, keyboard submission, and reconnect are disabled while recovery proceeds. Disconnect remains available.                                                                                                                                                 |
| `closed`                      | Session-ended explanation and return-to-pairing action, which opens a fresh page because `disconnect()` leaves the hook in `closed`.                                                                                                                                                                                                                                                    |
| `error`                       | Hook-provided error with guidance keyed by `errorCode` for signaling, expiration, peer departure, authentication, direct/relay availability, interruption, and protocol failures; fresh-page recovery action.                                                                                                                                                                           |

The header reports session status through a polite live region. Incoming text is announced in a conversation log. Errors use alerts. Native controls have labels, visible focus states, and touch-friendly sizing. The layout adapts to narrow screens and respects reduced motion. Theme switching uses the existing `next-themes` provider.

Signaling status is independent of peer status. An offline/connecting/reconnecting signaling service does not disable a connected chat or imply its peer connection has failed. Retired signaling is explained and hides Reconnect because a fresh pair is needed for future reconnection. Otherwise Reconnect calls `retryConnection`, and is disabled throughout recovery to avoid resetting it.

Expandable connection details show mode, selected route, optional RTT, elapsed session duration, signaling state, recovery attempt, and relay credential availability (unknown/available/unavailable). Credentials do not guarantee relay reachability. The duration timer is cleaned up on unmount or timestamp change. Export diagnostics downloads the hook’s safe JSON as `pair-diagnostics.json`, reports download errors, removes its temporary anchor, and revokes its Blob URL after dispatch or on unmount. No UI state or message contents are added to the export.

No file transfer controls are offered. “Text first. Files next.” is roadmap copy only. Privacy copy distinguishes encrypted WebRTC text from signaling/relay metadata visibility.

Dependencies: existing `@base-ui/react` Button, `lucide-react`, `next-themes`, `qrcode.react`, and `cn`. The additional small shadcn-style UI primitives are implemented locally to avoid dependency-manifest changes.
